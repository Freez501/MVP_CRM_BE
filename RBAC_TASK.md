# 📋 ТЗ: Внедрение ролевой модели (RBAC) и изоляция интерфейса

> Цель: настроить права доступа в интерфейсе на основе ролей из Supabase (admin, partner, staff), чтобы заготовщик не видел финансовые данные и клиентов, а админ мог управлять командой. Соблюдать Правило 5 (сначала план).

---

## 🎯 ЧТО ДЕЛАЕМ: ОБЗОР

1. **Доработка `AuthContext`**: при логине пользователя нужно дополнительно запрашивать его `role` и `name` из таблицы `public.profiles`.
2. **Ролевые роуты (Protected Routes)**: ограничить доступ к страницам на основе роли.
   - `staff` (Заготовщик) видит ТОЛЬКО `/calculator` и `/database`.
   - `partner` (Партнёр) видит всё, кроме настроек команды.
   - `admin` (Владелец) видит всё.
3. **Изоляция UI (Сайдбар)**: скрыть недоступные пункты меню в левом сайдбаре в зависимости от роли текущего юзера.
4. **Страница «Команда» (`/team`)**: новая страница (доступна только для admin), где выводится список пользователей из таблицы `profiles`.

---

## 🛠️ ПОШАГОВЫЙ ПЛАН РЕАЛИЗАЦИИ

### ШАГ 1: Извлечение роли в `AuthContext.tsx`

Сейчас `AuthContext` (или где вы храните сессию) получает только `user` из `supabase.auth.getUser()`. 
Необходимо:
1. После получения `user`, сделать запрос: 
   `const { data } = await supabase.from('profiles').select('role, name').eq('id', user.id).single()`
2. Сохранить `role` и `name` в стейт контекста.
3. Экспортировать их из хука `useAuth()`.

### ШАГ 2: Настройка доступа к роутам (`App.tsx` и `ProtectedRoute.tsx`)

1. Доработать компонент `<ProtectedRoute>` (или создать `RoleRoute`), чтобы он принимал массив разрешённых ролей: `allowedRoles={['admin', 'partner']}`.
2. Обернуть роуты в `App.tsx`:
   - `/dashboard`, `/clients`, `/events` -> `allowedRoles={['admin', 'partner']}`
   - `/team` (новая) -> `allowedRoles={['admin']}`
   - `/calculator`, `/database` -> `allowedRoles={['admin', 'partner', 'staff']}`
3. Если юзер заходит туда, куда ему нельзя — редирект на доступную ему страницу (например, staff -> `/calculator`).

### ШАГ 3: Адаптация Сайдбара (`Sidebar.tsx`)

1. Получить `role` из `useAuth()`.
2. Отфильтровать массив элементов меню навигации (`navItems`).
   - Исключить Дашборд, Воронку и Клиентов, если `role === 'staff'`.
   - Показывать пункт "Команда" только если `role === 'admin'`.

### ШАГ 4: Создание страницы Команда (`src/pages/Team.tsx`)

1. Создать новую страницу, добавить её в роутер.
2. При монтировании делать `SELECT * FROM profiles`.
3. Вывести красивую таблицу или сетку карточек с сотрудниками:
   - Имя
   - Email
   - Роль (с красивым бейджом: Владелец, Партнёр, Заготовщик)
   - Дата регистрации
